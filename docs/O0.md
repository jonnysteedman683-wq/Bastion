# O0: the recursive self-improving agent

O0 is the fleet's most powerful autonomous agent: a **recursive self-improving** system governed
by an immutable constitution and an append-only capability ledger. It evolves itself through a
strict flywheel: observe  hypothesize  implement  verify  promote, where every promotion
must pass a constitution audit and demonstrate measurable capability improvement.

Unlike population-based simulators, O0 is a **single embodied agent** that mutates its own
source, memory, and goals. It is a watcher on the ledger: it observes, learns, and reports, but
does not execute arbitrary tasks from external requests.

## Connecting O0 to Bastion

O0 connects to Bastion through the UniSync ledger as a watcher agent. It posts `heartbeat` events
to report its status and `memory.write` events to share consolidated knowledge with the fleet.

### Ledger-based connection (recommended)

For full integration with the fleet's ledger:

1. **Roster row.** Add O0 to the ledger's agent roster:
   ```sql
   insert into public.unisync_agents (name, role, repos)
   values ('o0', 'watcher', '{}') on conflict (name) do nothing;
   ```

2. **Ledger token.** Generate a secure token:
   ```bash
   python -c "import secrets; print(secrets.token_urlsafe(32))"
   ```
   Save it as the Bastion repository secret `UNISYNC_O0_TOKEN`, then store only its hash:
   ```sql
   insert into public.unisync_tokens (agent, token_hash, kinds)
   values ('o0', encode(sha256('<token>'::bytea), 'hex'), '{heartbeat,memory.write}');
   ```

3. **Environment.** Set these in O0's runtime:
   - `UNISYNC_GATEWAY_URL`: the UniSync gateway URL (repository variable, not secret)
   - `UNISYNC_O0_TOKEN`: the token from step 2 (secret)

4. **Reporting.** Modify O0's flywheel to post events after each iteration:
   - On flywheel start: `heartbeat` with status "observing"
   - On successful promotion: `memory.write` with the promotion summary
   - On flywheel completion: `heartbeat` with status and capability metrics

### Report-based connection (alternative)

For simpler integration using the Bastion report tool:

1. **Add to sources.json** (already done in Bastion's `services/command-centre/sources.json`)
2. **Generate an ingest key** and add it to the command centre's `INGEST_AGENT_KEYS`:
   ```bash
   python -c "import secrets; print(secrets.token_urlsafe(32))"
   ```
3. **Set environment variables** where O0 runs:
   - `BASTION_URL`: the command centre URL (e.g., `https://bastion.example.com`)
   - `BASTION_INGEST_KEY`: the key from step 2
4. **Wrap O0's main command** with the report tool:
   ```bash
   python -m tools.report run --label "O0 flywheel" -- python -m o0.main
   ```

## What O0 reports

| Event Kind | When | Summary Example |
| --- | --- | --- |
| `heartbeat` | Start of flywheel iteration | "O0 flywheel started: observing ledger tail" |
| `memory.write` | Successful promotion | "Promoted: added vector search to nucleus (capability +0.12)" |
| `heartbeat` | Flywheel complete | "Flywheel complete: 1 promotion, 3 rejected, capability: 42.7" |
| `heartbeat` | Audit failure | "Constitution audit failed: attempted to weaken invariant 3.2" |

## Safety

- O0 **never** accepts external tasks or instructions through Bastion
- All promotions are constitution-bound and verified
- Memory writes are sanitized: no code, no secrets, no instructions
- The capability ledger is append-only with sha256 receipts

## One-time setup checklist

- [ ] Roster row added to `public.unisync_agents`
- [ ] Token generated and stored as `UNISYNC_O0_TOKEN` secret
- [ ] Token hash stored in `public.unisync_tokens` with kinds `{heartbeat,memory.write}`
- [ ] O0 configured with `UNISYNC_GATEWAY_URL` and `UNISYNC_O0_TOKEN`
- [ ] O0's reporting code integrated (or using `tools.report` wrapper)
- [ ] First heartbeat posted successfully

## Revocation

To revoke O0's access:
```sql
update public.unisync_tokens set revoked_at = now() where agent = 'o0';
```
